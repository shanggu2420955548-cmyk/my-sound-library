# 个人游戏音效库开发路线

更新日期：2026-08-21

本项目是从 `transcriptionist-v3` fork 出来的自用音效库管理工具。目标不是做一个一次性交付的软件，而是做一个免费、本地优先、可长期修改优化的游戏音效工作台。

- 上游来源：`lid664951-crypto/transcriptionist-v3`

## 1. 仓库边界

GitHub 只管理这些内容：

- Python / PySide6 源码。
- 配置模板、默认规则、默认标签体系。
- 文档、路线图、开发脚本、测试代码。
- 小体积、可公开、可再分发的测试夹具。

GitHub 不管理这些内容：

- 真实购买、下载、整理过的音效包。
- 本地数据库、缓存、索引、去重指纹、波形缓存。
- AI 生成音效、在线资源下载结果、Unity 导出包。
- Freesound、Kling、OpenAI-compatible provider 等 API Key。
- 打包产物、安装包、临时压测结果。

原则：真实素材只在本地硬盘管理，仓库只保存“管理工具本身”。

## 3. 功能开发路线

### P1：音效包导入

目标：随时导入新音效包，不污染已有库，不产生重复脏数据。

要做：

- 支持选择一个或多个本地音效包目录导入。
- 导入前扫描格式、数量、体积、目录结构。
- 导入时记录来源包、原始路径、导入时间。
- 支持跳过、覆盖、重命名、保留两份等冲突策略。
- 导入失败不影响整批任务继续。

完成标准：

- 同一个音效包重复导入不会制造重复记录。
- 中断后重新导入可以恢复或重新扫描。
- 常用格式至少覆盖 `wav`、`mp3`、`flac`、`aiff`、`ogg`。

### P2：去重与相似音效识别

目标：减少重复素材，让大量音效包合并后仍然干净。

要做：

- 文件级去重：大小、修改时间、哈希。
- 音频级去重：时长、采样率、声道、音频指纹。
- 相似音效提示：同一素材不同格式、不同命名、轻微裁剪。
- 去重结果只提示和归档，不自动删除真实文件。

完成标准：

- 精确重复能稳定识别。
- 疑似重复能给出相似原因。
- 删除或归档动作必须可撤销。

### P3：搜索与浏览

目标：让找声音比翻文件夹快。

要做：

- 文件名、路径、标签、备注、来源包的模糊搜索。
- 中文、英文、拼写片段都能搜索。
- 支持格式、时长、采样率、声道、收藏、来源包筛选。
- 卡片视图、表格视图、波形预览、播放状态联动。

完成标准：

- 万级素材下搜索反馈足够快。
- 搜索结果能直接播放、定位、拖拽或导出。
- 切换视图不丢当前选择。

### P4：自动分类与标签

目标：先把已有大量素材粗分类，再逐步变细。

要做：

- 建立适合游戏音效的分类体系：UI、脚步、武器、怪物、环境、魔法、爆炸、载具、语音等。
- 基于文件名和目录名先做规则分类。
- 接入 AI 打标后补充语义标签和置信度。
- 标签支持手动修正，并能反哺规则。

完成标准：

- 新导入素材能自动进入一个可解释的初始分类。
- 低置信度标签会被标记出来，不假装完全正确。
- 手动修改不会被下一次自动任务随意覆盖。

### P5：GPT/AI 辅助

目标：AI 帮忙命名、分类、补标签、生成缺失音效，但不替代本地库主线。

要做：

- 使用本地配置或环境变量读取 API Key。
- 根据文件名、目录、波形/音频特征生成候选名称。
- 批量标签建议支持预览、确认、撤销。
- 缺失音效生成结果进入待审核区，再决定是否导入主库。

完成标准：

- API Key 不写入 Git，不出现在日志。
- AI 结果默认是候选项，确认前不改真实文件。
- 每次 AI 批处理都有任务记录和失败重试。

### P6：Unity 导出

目标：把选中的音效快速交给 Unity 使用。

要做：

- 支持拖拽文件到 Unity 项目或资源目录。
- 支持导出选中音效到指定文件夹。
- 支持按标签、分类、来源包批量导出。
- 可选生成 Unity 友好的目录结构和命名。
- 导出产物不进入本仓库。

完成标准：

- 导出不会移动或破坏原始素材。
- 同名文件有稳定冲突策略。
- `*.unitypackage`、`exports/unity/`、`data/exports/unity/` 默认被 Git 忽略。

### P7：自用打包与长期维护

目标：保持一个自己随时能用、能改、能打包的版本。

要做：

- 保持源码运行入口可用。
- 保持 Windows 打包链路可用。
- 每完成一个阶段补充更新日志。
- 重要规则和数据结构写入文档，避免以后忘记。

完成标准：

- 新电脑 clone 后能按文档跑起来。
- 本机真实素材库不依赖 GitHub。
- 打包产物不包含真实素材、数据库、缓存或密钥。

## 4. 推荐开发顺序

1. 完成 `.gitignore` 和仓库边界文档。
2. 补 `.env.example`，只放字段名和说明。
3. 梳理现有导入/扫描代码，找最短可用链路。
4. 做导入任务记录和冲突策略。
5. 加精确去重。
6. 加模糊搜索和筛选体验。
7. 加自动分类规则。
8. 接 AI 命名、打标、生成音效。
9. 做 Unity 拖拽/导出。

## 5. 每次提交前检查

```powershell
git status --short
git diff --stat
git status --ignored --short
```

看到真实素材、数据库、缓存、索引、AI 生成音效、Unity 导出包、`.env` 或密钥文件时，先停下来处理，不提交。
